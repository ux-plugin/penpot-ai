## Updated Issue Details

### Handling SSE and Non-SSE States
- The UI should handle both SSE and non-SSE states when receiving port info from the backend.

### POST to /handshake
- Upon receiving the port, the UI must POST to `/handshake` on the companion app, using AES-GCM encryption. This key should be generated in the UI and fetched/persisted via the backend API.

### Key Management
- The UI is responsible for generating the nonce and storing the key validity period.

### Handshake Failure Management
- The UI must handle handshake failures by retrying the key fetch from the backend and reporting errors to the user.

### Lifecycle and Error Handling Steps
1. **Initiate Handshake:** When the port is received, generate the nonce and fetch the key from the backend.
2. **POST to Companion App:** Use the generated nonce and key to POST to `/handshake`.
3. **Handle Response:** If the handshake is successful, proceed with the connection. If it fails, retry fetching the key and attempt the handshake again.
4. **Error Reporting:** If an error occurs during any stage, report it to the user with appropriate messaging.
